== Introduction

What is a dependency? Class A has a dependency on Class B when it interacts with it in any way. For example, Class A executes a method on an instance of Class B. You typically don't instantiate class dependencies when using Micronaut Framework's dependency injection engine. Instead, you rely on the framework to provide dependency instances.

NOTE: In Micronaut Framework documentation, we often use the terms `bean` and `dependency` interchangeably.

== JSR-330

Micronaut Framework implements the https://javax-inject.github.io/javax-inject/[JSR-330 - Dependency Injection for Java specification].

== jakarta.inject vs javax.inject

Early versions of Micronaut Framework used `javax.inject` annotations. Due to trademark restrictions imposed on the `javax.*` namespace, Micronaut Framework switched from `javax.inject` to `jakarta.inject` annotations. Since https://micronaut.io/2021/03/09/micronaut-2-4-released/[version 2.4], Micronaut Framework supports `jakarta.inject` annotations. Moreover, Micronaut Framework switched to `jakarta.inject` as the set of annotations included by default, and we strongly encourage you to use `jakarta.inject` going forward.

== Dependency Injection Types

Micronaut Framework offers three types of dependency injection:

=== Constructor Injection

In constructor-based injection, Micronaut Framework provides the dependencies required for the class as arguments to the constructor.

source:constructor/MessageController[]

:exclude-for-languages:python
If your class has multiple constructors, Micronaut Framework searches for one constructor annotated with `jakarta.inject.Inject`.
:exclude-for-languages:

=== Field Injection

:exclude-for-languages:python
With field injection, Micronaut fulfills the injection endpoints for fields annotated with `jakarta.inject.Inject`.
:exclude-for-languages:

:only-for-languages:python
With field injection, declare an attribute with its dependency type and `Inject` in `Annotated` metadata.
:only-for-languages:

source:field/MessageController[]

:exclude-for-languages:python
Field injection makes it harder to understand a class's requirements, making it easier to get a `NullPointerException` when testing a class using field injection. We recommend you use <<Benefits of Constructor Injection, constructor injection>>.

WARNING: The previous code sample uses a field with the default access modifier. There are four types of access modifiers available in Java: `private`, `protected`, `public`, and the default. Field injection works with all of them. However, field injection in a field with the `private` access modifier requires reflection. Thus, we recommend you do not use `private`.

NOTE: You use field injection in test classes annotated with `MicronautTest`. Micronaut does not instantiate the test class. Thus, you cannot use constructor injection in those classes.

NOTE: When using https://micronaut-projects.github.io/micronaut-spring/latest/guide/[Micronaut for Spring], you can also use Spring's `@Autowired` annotation for field injection. To learn more, read the guide: https://micronaut-projects.github.io/micronaut-guides/latest/micronaut-spring-boot.html[Run a Spring Boot application as a Micronaut application].
:exclude-for-languages:

:only-for-languages:python
Field injection allows an object to be created without its required collaborators. Accessing an uninjected attribute then fails. We recommend you use <<Benefits of Constructor Injection, constructor injection>>.
:only-for-languages:

=== Benefits of Constructor Injection

When possible, we recommend you use constructor injection for several reasons:

**Clear Contract**

Constructor injection clearly expresses the requirements of the class and requires no additional annotation.

**Immutability**

:exclude-for-languages:python
Constructor injection allows you to define `final` dependencies, creating immutable objects.
:exclude-for-languages:

:only-for-languages:python
Constructor injection assigns dependencies when the object is created. Python attributes remain mutable unless the class enforces immutability.
:only-for-languages:

**Identifying code smells**

Constructor injection helps you easily identify if your bean depends on too many other objects.

**Testing**

Constructor injection simplifies writing both unit and integration tests. The constructor forces us to provide valid objects for all dependencies. 
:exclude-for-languages:python
Thus, it decreases the chance of a NullPointerException occurrence during testing.
:exclude-for-languages:
