common:header.adoc[]

https://docs.oracle.com/en/database/oracle/oracle-database/26/ddscg/[Oracle Deep Data Security] moves data access control from the application into Oracle Database. The database knows who the end user is, because the application propagates the end-user identity obtained from an identity provider, such as Microsoft Entra ID, on every JDBC connection. Oracle *data roles* then decide which rows and columns each user can see, and the application escalates privileges for specific operations by enabling a data role for the duration of a call.

In this guide, you will build the Micronaut version of the https://docs.oracle.com/en/database/oracle/oracle-database/26/ddscg/configure-oracle-deep-data-security-sample-application.html[Oracle Deep Data Security sample application]. Users sign in with Microsoft Entra ID. The application lists the employees of the `HR` schema and a salary summary that only a compensation analyst can compute:

image::micronaut-oracle-deep-data-security.png[]

The application uses:

* https://micronaut-projects.github.io/micronaut-security/latest/guide/#oauth[Micronaut Security OAuth 2.0] to authenticate users with Microsoft Entra ID via OpenID Connect.
* https://micronaut-projects.github.io/micronaut-security/latest/guide/#ojdbcExtensions[Micronaut Security OJDBC Extensions] to hand the authenticated user to Oracle JDBC as an *End User Security Context*.
* The Oracle JDBC https://github.com/oracle/ojdbc-extensions/tree/main/ojdbc-provider-azure[Azure provider] to authenticate the connection pool to the database with an Entra ID service principal token.
* https://micronaut-projects.github.io/micronaut-data/latest/guide/#jdbc[Micronaut Data JDBC] to query the `HR.EMPLOYEES` table, and `@RunAs` to run the salary summary query with the `COMPENSATION_ANALYST` data role.

* https://www.docker.io/gettingstarted/#h_installation[Docker] installed to run Oracle Database, and to run the tests with https://www.testcontainers.org[Testcontainers].
* A https://learn.microsoft.com/entra/fundamentals/[Microsoft Entra ID] tenant where you can register applications.

== Oracle Database

=== Run Oracle Database via Docker

Run https://github.com/gvenzl/oci-oracle-free[Oracle Database Free] with Docker:

[source,bash]
----
docker run -d --name micronaut-deep-data-security \
  -p 1521:1521 -p 2484:2484 \
  -e ORACLE_PASSWORD='YourStrongPassword1' \
  -v oracle-free-data:/opt/oracle/oradata \
  gvenzl/oracle-free:23.26.2-full
----

Expose both ports: `1521` for plain TCP connections and `2484` for TLS (TCPS) connections, which Deep Data Security requires. Use the `23.26.2-full` image or a later one; previous versions do not support Deep Data Security.

=== Generate Wallets and Certificates

Generate the server wallet and a self-signed certificate as described in https://docs.oracle.com/en/database/oracle/oracle-database/26/ddscg/generate-wallets-and-certificates-springboot.html[Generate Wallets and Certificates]. Because the database runs in a container, create the wallet in `/opt/oracle/wallets/server` instead of `/u01/app/oracle/wallets/server`.

Connect to the container:

[source,bash]
----
docker exec -it micronaut-deep-data-security bash
----

Create the server wallet and a self-signed certificate. Use `localhost` as the certificate common name, since the application connects to the container through `localhost`, and choose a wallet password, for example `WalletPass123!`:

[source,bash]
----
mkdir -p /opt/oracle/wallets/server
orapki wallet create -wallet /opt/oracle/wallets/server -pwd WalletPass123! -auto_login
orapki wallet add -wallet /opt/oracle/wallets/server -dn "CN=localhost,O=Oracle,C=US" -keysize 2048 -self_signed -validity 3650 -pwd WalletPass123!
----

=== Copy the Wallet to the Host

The application validates the database certificate with the auto-login wallet, `cwallet.sso`. Copy the wallets from the container to your computer:

[source,bash]
----
docker cp micronaut-deep-data-security:/opt/oracle/wallets ~/oracle-wallets
----

You will reference `~/oracle-wallets/server/cwallet.sso` with the `ORACLE_WALLET_TRUSTSTORE` environment variable.

=== Configure Database Network Settings

https://docs.oracle.com/en/database/oracle/oracle-database/26/ddscg/configure-database-network-settings.html[Configure the database listener and network layer] to accept TCPS connections on port `2484` and to enable token-based authentication. Both configurations use the server wallet you created.

Connect to the container again and go to the network configuration directory:

[source,bash]
----
docker exec -it micronaut-deep-data-security bash
cd $ORACLE_HOME/network/admin
----

Edit `listener.ora`. Add the wallet location and the TCPS address. Oracle recommends the fully qualified domain name of the database server as `HOST`; inside the container, use `0.0.0.0`:

[source]
.listener.ora
----
WALLET_LOCATION = (SOURCE = (METHOD = FILE) (METHOD_DATA = (DIRECTORY = /opt/oracle/wallets/server)))

TLS_CLIENT_AUTHENTICATION = FALSE

LISTENER =
 (DESCRIPTION_LIST =
  (DESCRIPTION =
   (ADDRESS = (PROTOCOL = IPC)(KEY = EXTPROC_FOR_FREE))
   (ADDRESS = (PROTOCOL = TCP)(HOST = 0.0.0.0)(PORT = 1521))
   (ADDRESS = (PROTOCOL = TCPS)(HOST = 0.0.0.0)(PORT = 2484))
  )
 )

DEFAULT_SERVICE_LISTENER = FREE
----

Edit `sqlnet.ora`. This enables token-based authentication and points the network layer to the server wallet for TLS:

[source]
.sqlnet.ora
----
NAMES.DIRECTORY_PATH = (EZCONNECT, TNSNAMES)
# See https://github.com/gvenzl/oci-oracle-xe/issues/43
DISABLE_OOB=ON
BREAK_POLL_SKIP=1000

# --- Authentication ---
SQLNET.AUTHENTICATION_SERVICES = (BEQ, TOKENAUTH)

# --- TLS Configuration ---
TLS_CLIENT_AUTHENTICATION = FALSE
TLS_SERVER_DN_MATCH = TRUE

# Prevents conflicts between Native Encryption and TLS
SQLNET.IGNORE_ANO_ENCRYPTION_FOR_TCPS = TRUE

WALLET_LOCATION = (SOURCE = (METHOD = FILE) (METHOD_DATA = (DIRECTORY = /opt/oracle/wallets/server)))
----

Restart the listener and force the database to register its services with it:

[source,bash]
----
lsnrctl stop
lsnrctl start
sqlplus / as sysdba
----

[source,sql]
----
ALTER SYSTEM REGISTER;
----

Check with `lsnrctl status` that the listener accepts TCPS connections on port `2484` and that the `FREEPDB1` service is registered.

=== Micronaut Security OJDBC Extensions

The https://micronaut-projects.github.io/micronaut-security/latest/guide/#ojdbcExtensions[Micronaut Security OJDBC Extensions] module registers an Oracle JDBC `EndUserSecurityContextProvider`. === Azure Token Provider for JDBC

The Oracle JDBC Azure provider authenticates the connection pool to Oracle Database with a Microsoft Entra ID service principal token:

dependency:ojdbc-provider-azure[groupId=com.oracle.database.jdbc,version=1.1.0]
